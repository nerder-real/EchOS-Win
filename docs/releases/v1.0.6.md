# EchOS-Win v1.0.6

把 Flutter / Dart SDK 基线与项目版本统一抬到当前稳定版，并完成全链路验证。

## 升级

- **SDK 下限抬到 Dart 3.13 / Flutter 3.47**

  `pubspec.yaml` 的 `environment` 由 `sdk: ^3.12.2` 改为 `sdk: ^3.13.0`，
  并补上此前缺失的 `flutter: '>=3.47.0'`。

  本机与 CI（`.github/workflows/build-windows.yml` 已锁 `flutter-version: 3.47.4`）
  现均为 Flutter 3.47.4 / Dart 3.13.3，同一 SDK 解析出同一套依赖，发版产物可复现。
  `pubspec.lock` 除 SDK 约束两行外**依赖版本零改动**，升级不会带入未验证的新依赖。

- **vendored 插件 SDK 约束现代化**

  `third_party/menu_base` 原为 `sdk: ">=2.12.0 <3.0.0"`（Dart 2 时代遗留），
  `third_party/tray_manager` 为 `">=3.0.0 <4.0.0"`，与主工程三套约束各说各话。
  现统一到 `^3.13.0` / `flutter: ">=3.47.0"`。

  随之处理 SDK 升级后新生效的 lint：移除 `menu_base.dart` 里已无作用的
  `library menu_base;`（`unnecessary_library_name`），`menu_base` 的
  `flutter_lints` 同步升到 `^6.0.0`。

- **项目版本 1.0.5+6 → 1.0.6+7**

  `pubspec.yaml` 的 `version` 与 `app_version.dart` 的自报版本默认值同步为 `1.0.6`。
  发布构建仍由 CI 用 `--dart-define=ECHOS_VERSION=` 从标签注入，这里只影响本地构建。

## 验证

- `flutter pub get`：正常解析
- `flutter analyze`：零问题
- `flutter build windows --release`：编译通过

## 说明

- 依赖本身在上个版本已升到最新（`file_picker 12.3.0` / `window_manager 0.5.2` 等），
  本次 `flutter pub outdated` 显示直接依赖全部 up-to-date；
  仅 `material_color_utilities` 有 0.13.1 可用，但它由 Flutter SDK 声明钉住，无法独立升级。
- 本地开发仍需 Flutter **3.47.4**（见 README「本地构建」）。
