# EchOS-Win v1.0.8

完善日志文件的清理规则，并把运行时产生的数据收拢到应用数据目录。

## 改进一：日志文件的大小上限

`error.log` 原先是唯一没有大小上限的日志，`kernel.log` 的上限则小到撑不过
一个晚上。两处都只调参数，不改写入逻辑。

### error.log 补上 2MB 上限

它原先只在每次启动 `startNewSession()` 时清空一次，会话内如果持续报错就会
一直追加下去。现在超过 2MB 就整体清空重写，并先写一行
`=== error.log 超过 2MB，已清空重写 ===` 作为标记。错误日志的价值在时效，
不留旧内容，保证「最近的错误」始终可读。

### kernel.log 上限 1MB → 4MB

内核进程的 stdout/stderr **每一行**都会落盘到 `kernel.log`，而且它**不受
「日志级别」设置控制**——把日志级别调到「关闭」只会停掉界面日志，内核日志
照样全速写。它是唯一高频且唯一跨会话累积的日志文件。

实测播放视频等高频场景约 **480 KB/h**，1MB 撑不到 3 小时就轮转一次，想回看
几小时前的隧道失败原因时已经被覆盖掉了。提到 4MB 后，高峰场景覆盖约 8 小时，
日常使用约一天；加上轮转出的 `kernel.prev.log`，总覆盖 16 小时到 2 天。

### 日志文件上限一览

| 文件 | 上限 | 机制 |
| --- | --- | --- |
| `latest.log` | 8 MB | 写满轮转 → `previous.log` |
| `previous.log` | 8 MB | 只留一份 |
| `kernel.log` | **4 MB**（原 1 MB） | 超限轮转 → `kernel.prev.log` |
| `kernel.prev.log` | **4 MB**（原 1 MB） | 只留一份 |
| `error.log` | **2 MB**（新增） | 超限清空重写 |
| `selfcheck.log` | 1 MB | 超限删除重建 |

磁盘封顶约 27 MB（原 21 MB）。

## 改进二：运行时数据收拢到应用数据目录

托盘图标和更新看门狗日志原先散落在系统临时目录里，现在统一归到
`%APPDATA%\EchOS` 下，与配置和日志放在一起：

- 托盘图标 → `%APPDATA%\EchOS\tray\`
- 更新看门狗日志 → `%APPDATA%\EchOS\logs\`

好处是查找和备份时只需关注一个目录，不再受系统临时目录清理的影响。
（自替换用的批处理是一次性文件，用完即删，仍留在系统临时目录。）

## 升级说明

- 覆盖安装即可，配置存放在 `%APPDATA%\EchOS`，不受影响。
- 自报版本 1.0.7 及以下的客户端均可收到本次更新。
- 已有的日志文件不会被清理，新的大小上限从本次更新后开始生效。
