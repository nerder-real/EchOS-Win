# EchOS-Win v1.0.9

本次共六项修复，集中在三块：**分流模式**相关的交互与断网、启动与系统代理的
时机、以及**桌面图标**显示异常。

| # | 问题 | 影响 |
| --- | --- | --- |
| 一 | 切换分流模式后药丸高亮不跟随 | 看起来像"点了没反应" |
| 二 | 重启代理期间拆掉系统代理 | 程序短暂断网 |
| 三 | 启动要等自检通过才接管代理 | 启动后十几秒上不了网 |
| 四 | 快捷方式未显式指定图标 | 依赖 exe 抠图，易出残影 |
| 五 | 图标 AND 掩码全零 | 图标圆角处黑边/杂色 |
| 六 | 还原系统代理到 10808 | 退出后代理指向失效端口 |

## 修复一：切换分流模式后药丸不跟随高亮

现象：代理运行中切换「绕过中国大陆 / 黑名单 / 全局」，日志显示切换成功、内核也
按新模式重启了，但界面上的高亮药丸停在原来的位置，看起来像"点了没反应"。

原因在 Flutter 的重建机制上。主页上的模式切换控件是以 `const` 实例挂上去的，
父级重建时 Flutter 发现 widget 实例相同（`identical`）就会跳过整棵子树 ——
控件根本没机会读到新的 `routeMode`。

改法是让控件自己订阅状态：用 `AnimatedBuilder(animation: app, ...)` 包一层，
模式变化由它自己响应，不再依赖父级传下来的重建。主页上另外六个控件经排查在
使用处都没有 `const` 前缀，不受影响，只改这一处。

顺带把切换日志写清楚：会记录"从哪个模式 → 哪个模式"、代理未运行时说明下次启动
生效、重启结束后说明结果（以前失败时日志停在"正在重启…"，看不出到底成没成）。

## 修复二：重启代理期间不再拆掉系统代理

这是"用着 EchOS，某些程序（比如 WorkBuddy）突然断网"的根因。

### 问题

切换分流模式、切换服务器、应用自定义规则、保存参数后重启 —— 这些操作都要重启
内核。每次重启的几秒钟里，走系统代理的程序会连不上网。

### 根因

原来的流程是：

```
切模式 → 停内核 → 还原系统代理 → 启动新内核 → 等端口就绪 → 自检 → 重新接管系统代理
                  ↑ 这里就断了            ↑ 到这里才恢复
```

本地端口（30000 / 30001）是固定的，新内核起来后原来的系统代理设置本来依然有效，
"还原再接管"这中间的一步其实是多余的。而这一步的代价很实在：中间那 **2~6 秒**
系统代理是**关闭**状态，此时程序直连境外域名必然超时，表现就是"什么都没干，
网络突然断了"。

（补充：还原时写回的是接管前的系统代理设置。如果那份备份里的代理程序已经不在
了，这段时间的断网会更彻底。）

### 现在的做法

重启内核时**保留系统代理不动**：

- 内核重启本身仍有 1~6 秒空档，但程序拿到的是 `connection refused`（快速失败，
  多数程序会自己重试），远好过几十秒的直连超时。
- `start()` 有多条提前返回的路径（没选服务器 / 配置不完整或未保存 / 内核起不来 /
  端口被占用 / 端口一直未就绪）。任何一条失败都会留下"系统代理指向已经死了的本地
  端口"，比直接断网更糟，所以加了兜底：重启后若代理没跑起来，就还原系统代理。
- 同时给内核进程加了「代号」。`stop → start` 时旧内核的退出回调往往晚到，会把刚
  起来的新内核状态打回去。现在旧内核的迟到退出会被忽略。

一并修掉的四处场景（它们的性质完全相同：都是重启内核、端口不变）：

| 操作 | 说明 |
| --- | --- |
| 切换分流模式 | 绕过中国大陆 / 黑名单 / 全局 |
| 切换服务器 | 换一个节点 |
| 应用自定义规则 | 保存规则后重启 |
| 保存参数后重启 | 「保存」按钮触发的重启 |

**用户主动关闭代理、退出程序、自检失败自动关闭**等路径不受影响，仍然照旧还原
系统代理，不会在退出后留下失效的代理设置。

## 修复三：启动与自检解耦，代理启动后不再长时间上不了网

「启动了代理，但要等好一阵网页才打得开」——原因是启动流程把两件事缠在了一起：

```
旧：内核起来 → 等端口就绪 → 跑自检(隧道探针) → 通过后才接管系统代理
                                  ↑ 慢节点能拖十几秒
新：内核起来 → 等端口就绪 → 立刻接管系统代理
                        → 自检照跑，只负责判断隧道通不通，不通就回滚
```

实测一次启动里，从端口就绪到真正接管隔了 **22 秒**，这段时间系统代理是关的，
浏览器直连，境外站点全挂。现在这段窗口压到了端口就绪的耗时。

自检并没有被削弱，只是不再当"准入门槛"：

- 隧道通 → 一切照旧
- 隧道不通 → 自检失败走 `stop()`，会自动还原系统代理，不会留下指向死端口的
  代理设置。因为提前接管了，失败时走的是"已接管 → 关闭并还原"这条更干脆的分支

## 修复四：桌面快捷方式图标显式指定

桌面和开始菜单的快捷方式原先都没写 `IconFilename`，靠 Windows 从 `echos.exe`
里抠图标、再进图标缓存。抠图或缓存任一环节出问题（重装时 exe 正在被替换最容易
中招），桌面就显示成残影、杂色，或者把低分辨率小图拉伸成大图标。

现在改为随包安装一份 `logo.ico` 到安装目录，快捷方式显式指向它，与 exe 解耦。

## 修复五：图标 AND 掩码全零导致的黑角/杂色

这是上一版「重编码为 BMP 条目」时引入的**新问题**，也是"桌面图标脏"的直接成因。

### 现象

图标边缘（尤其圆角处）出现黑色杂边、残影，看起来像没擦干净的旧图。

### 根因

ICO 里每个 BMP 条目除了 32bpp 的 BGRA 数据（XOR），还带一张 1bpp 的 **AND
掩码**：某位为 1 表示"这个像素透明，别画"。

Windows 有两条渲染路径：现代路径按 alpha 通道做混合，老式 GDI 路径**只看 AND
掩码**、完全不理会 alpha。上一版重编码时掩码被写成全 0 —— 等于声明"一个透明像素
都没有"。于是老式路径把四个圆角的透明区当成实色画了出来，而那些像素的 RGB 是 0，
画出来就是**黑角**。

逐项核对的结果（掩码置位数应等于透明像素数）：

| 尺寸 | 掩码置位数 | 实际透明像素 | 结论 |
| --- | --- | --- | --- |
| 16×16 | 0 | 4 | 掩码失效 |
| 48×48 | 0 | 48 | 掩码失效 |
| 256×256 | 0 | 1846 | 掩码失效 |

### 修复

按 `alpha == 0 → 掩码位置 1` 重新生成七档尺寸的掩码，并与 alpha 通道逐像素核对：

| 尺寸 | 掩码置位数 | 透明像素 | 不符 |
| --- | --- | --- | --- |
| 16 / 24 / 32 / 48 / 64 / 128 / 256 | 4 / 9 / 20 / 48 / 108 / 478 / 1846 | 同左 | **0** |

同时确认了另外两件事，排除其它嫌疑：

- 重编码是**逐像素无损**的：BMP 版与原 PNG 版的半透明像素数逐档完全一致
  （1777 / 541 / 244 / 188 / 116 / 87 / 56），抗锯齿边缘没有丢失。
- 透明像素的 RGB 全是 0，不存在"透明区残留旧颜色"这类问题。

## 修复六：不再把系统代理还原到 10808

退出 EchOS 后，系统代理被还原成 `127.0.0.1:10808`。这个地址是 v2rayN 退出时留在
注册表里的僵尸值：代理开关本来是关的，所以它平时不生效，但 EchOS 会把"接管前读
到的 ProxyServer"原样写回去，看上去就像还原到了一个陌生地址。

现在的规则是：**只有接管前系统代理确实处于启用状态，才写回地址**；否则直接删掉
`ProxyServer` 这个僵尸值。

这样有两个好处：日志不再出现莫名其妙的地址；以后手动打开系统代理开关时，也不会
意外连到一个早就失效的端口。

还原日志也跟着改清楚了，会明确区分是「沿用接管前的配置」还是「关闭」。
