# EchOS-Win v1.1.0

本次是 v1.0.9 后的**功能版本**，集中在六块：**TUN 模式**上线、TUN 真机崩溃修复、
**DNS 污染**根因修复、**ECH 启动卡死**修复、启动/停止的**交互状态机**、以及托盘/日志/打包配套。

TUN 模式之前在内核里「编得出来但一直没接」，本版本把它接上并
glint out 了真机上出现的崩溃、断网、DNS 污染等硬故障。

| # | 问题/功能 | 影响 |
|---|---|---|
| 一 | TUN 模式上线：虚拟网卡接管全部流量 | 不依赖系统代理，覆盖不支持代理的进程（如 CMD / 游戏） |
| 二 | TUN 启动后本地端口监听顺序错误 → 客户端误判启动失败 | TUN 模式下代理起不来 |
| 三 | simple 协议不存在的 smux 连接池 → 空等 60 秒 | TUN 永远建不起来 |
| 四 | TUN 数据路径错误：走 smux 池 → 全报「无可用通道」 | 上了 TUN 也断网 |
| 五 | wintun.Session 值接收者 → `0xc0000005` 崩溃 | 关 TUN 时崩溃，系统代理也不恢复 |
| 六 | DNS 污染：运营商解析出假 IP，代理全超时 | 每次重启都失败（真机硬故障） |

## 一、TUN 模式上线（新功能）

### 功能

在「高级设置」里新增「启用 TUN 模式」开关：

- 开启后，内核会建一块 **Wintun 虚拟网卡**，接管 `0.0.0.0/0` 的全部流量；
- 不需要在浏览器/应用里手动设代理，所有进程（包括不支持代理的程序）自动走隧道；
- 需要**管理员权限**（建虚拟网卡、改路由表、改网卡 DNS），首次开启会弹窗以管理员身份重启。

### 与系统代理的共存策略

TUN 与「自动设置系统代理」**不互斥**：

- **配置层**：两者可以同时在设置里开着；
- **行为层**：TUN 生效期间系统代理**自动让位**（已接管会还原），但不改开关状态；
- **关 TUN 后**：内核重启，系统代理按原来的开关自动恢复接管。

这样就不像以前：开一次 TUN 就把系统代理开关永久关掉，用户下次想用时找不回来。

### 为什么必须随包带 `wintun.dll`

内核用 `LoadLibraryEx("wintun.dll", …, LOAD_LIBRARY_SEARCH_APPLICATION_DIR)` 加载它，
只认「与 `x-tunnel.exe` 同目录」或 `System32`。如果用户选便携版，默认不会有 `System32`，
所以安装包/便携版都必须带上 `wintun.dll`，否则点了开关只报错「加载 wintun.dll 失败」。

配套改了三处：

- `.github/workflows/build-windows.yml`：CI 构建时下载并校验 `wintun.dll`；
- `build_local.ps1`：本地构建时自动下载；
- `windows/runner/copy_bundle.cmake`：POST_BUILD 把 `wintun.dll` 和 `geoip.dat` / `geosite.dat` 一起拷到产物目录。

### 提权重启的锁交接

TUN 模式需要管理员权限，但 Windows 不允许运行中的程序直接提权，只能以管理员身份**重启**自己。
重启时老实例和新实例会短暂共存，如果锁文件不释放，新实例会误判「已有实例在跑」然后自己退出 —— 表现就是「点了开关，窗口闪一下，什么都没发生」。

把原先写在 `main.dart` 里的单实例逻辑抽成 `lib/services/instance_guard.dart`，
并在 `confirmElevation()` 里让老实例**先放锁、再退出**，确保新实例顺利接管。

## 二、TUN 启动后本地端口监听顺序错误

### 现象

TUN 模式下 Dart 侧等待本地端口（30000/30001）的时间线：
1. 内核启动，开始等 smux 通道就绪（最长 60 秒）；
2. 通道还没好，Dart 20 秒就把内核判定为「启动失败」并杀掉；
3. 但实际上内核正在正常工作，只是**本地端口还没开始监听**。

### 根因

内核的启动顺序在 TUN 模式下错了：本地 SOCKS/HTTP 监听的初始化放在了「等通道就绪」之后。
TUN 分支要等通道是因为它要在路由劫持全部流量之前确保隧道可用 —— 这没问题，
但端口监听只影响本机，完全可以提前。

### 改法

把端口监听（`30000` / `30001`）提到「等通道」之前。顺序变为：
1. 起本地端口（Dart 立刻能检测到）；
2. 等 smux 通道（最多 60 秒，simple 协议下直接跳过）；
3. 通道好后建 TUN。

## 三、simple 协议不存在的 smux 连接池

### 现象

TUN 模式下启动代理后一直「等通道」，60 秒后 Dart 判定超时杀掉内核。

### 根因

`protoSimple`（Worker-ECH.js）服务端用的是 `WebSocket` 握手，没有 smux 多路复用。
但 TUN 启动逻辑里无条件调了 `WaitForChannelReady(60s)`，而 simple 协议根本没建 smux 池 —— 这个函数会空等 60 秒，且它后面的 TUN 建网卡代码永远执行不到。

### 改法

按协议分支：

- `protoMux`（smux）→ 等通道就绪后再建 TUN；
- `protoSimple` → 直接跳过等通道，直接建 TUN。simple 是单流 WebSocket，握手即连。

## 四、TUN 数据路径错误

### 现象

TUN 能建起来，但所有流量都报「无可用 smux 通道」，等于断网。

### 根因

TUN 和本地代理是**两条独立数据路径**，但 TUN 分支有三处直接调了 smux 池的专用接口：

| 位置 | 错误写法 | 症状 |
|---|---|---|
| `tun_stack.go` TCP 出口 | `pool.openTCPStream()` | TCP 流量全废 |
| `tun_dns.go` DoH `DialTLSContext` | `pool.openTCPStream()` | DNS 全 SERVFAIL |
| `tun_stack.go` UDP 出口 | `pool.openUDPStream()` | UDP 关联建不起来 |

simple 协议没有 smux 池，这些调用直接返回 nil，流量全部卡住。

### 改法

TUN 里任何出站都走 `dialViaTunnel(target)`，内部按 `serverProtocol` 自动分流：
smux 用 `pool.openTCPStream()`，simple 用 `dialViaTunnel()`。

`outbound.rw` 统一用 `net.Conn`（`smux.Stream` 和 `simpleWSConn` 都实现了），
DoH 的 `DialTLSContext` 内部交给 `tls.Client`，安全。

### UDP 处理

simple 协议不支持 UDP（`simple_ws.go` 里 UDP 匹配数 = 0）。
走代理的 UDP 一律回 **ICMP 端口不可达**，促其回落 TCP ——
**不会**静默丢包（看起来像是网络不通），也**不会**偷偷直连（后者等于把流量泄漏到隧道外）。

## 五、关 TUN 时 `0xc0000005` 崩溃

### 现象

关闭 TUN 或退出应用时，偶发 `0xc0000005`（访问违例），应用直接崩掉，
系统代理也没机会还原。

### 根因

`wintun.Session` 的方法全是**值接收者**：

```go
func (session Session) End() { ...; session.handle = 0 }
```

`End()` 只改了函数参数里的副本，真正的 `t.session.handle` **仍是已释放的野句柄**。
`Close()` 唤醒 `dispatch` 协程后，它回头 `ReceivePacket(野句柄)` → 访问违例。

### 改法

- `ReadPacket` / `WritePacket` / `ReadWaitEvent` 加读锁 + `t.closed` 检查，关闭后返回 `net.ErrClosed`；
- `Close()` 里 `End()` 之后把 `t.session = wintun.Session{}` 清零 handle；
- `dispatch` 循环遇 `net.ErrClosed` 或 `ReadWaitEvent() == 0` 立即返回，不拿无效句柄空转。

## 六、DNS 污染导致代理彻底失效

### 现象

代理每次关闭再启动都失败，内核日志刷满 `dial tcp 8.134.121.112:443: i/o timeout`。
这个 IP 完全不属于你的服务器。

### 根因

代理服务器域名 `cdns.doon.eu.org` 真实指向 `www.nexusmods.com`（Cloudflare 托管、国内被墙），
运营商 DNS 把它解析成了一个**阿里云假 IP** `8.134.121.112`。内核信了假 IP，把全部流量拨向死地址。

**决定性证据**：用系统解析器查得到 `8.134.121.112`，用公共 DNS（223.5.5.5 / doh.pub）查得到正确的 `104.18.42.54` / `172.64.145.202`。两路结果不一致，就是**DNS 污染**。

### 改法

解析代理服务器域名时走**控制面 DNS**（配置里的 DoH/UDP），不直接信系统解析器：

1. **先问配置的 DoH/UDP DNS**，做 A / AAAA 记录查询；
2. **不可用时问内置 DoH 兜底**：`223.5.5.5` / `dns.alidns.com` / `doh.pub` / `1.1.1.1`（5 秒预算）；
3. **最后才退回系统解析器**，同时打警告：
   ```
   ⚠ 服务器域名 cdns.doon.eu.org 两路解析结果不一致：
      控制面 DNS=[172.64.145.202 104.18.42.54]，
      系统解析器=[2406:cb42:0:f13e::b394 8.134.121.112]。采用控制面 DNS 的结果
   ```

### 顺带修的：v6 污染

之前池子里混进过 `2406:cb42:0:f00e::49bd`，我误当成「v6 偏好问题」修掉了 ——
其实是污染的另一半（正确解析根本没有 AAAA）。这次又抓到一个**不同的**假 v6 `2406:cb42:0:f13e::b394`，
坐实污染每次给的假 IP 都不同。

`resolveServerIPv4` 现在改为：拿到 IPv4 就**只**返回 IPv4，绝不把 v6 混进轮转池；
一条 v4 都没有时才退回 v6。这样池子只有真 IP，每次建连都不会白超时。

### 为什么内置兜底是必需的

你另一台服务器配的 `udp://208.67.220.220:443`（OpenDNS 走 UDP 443）在国内大概率不通。
没有兜底就会退回系统解析器 → 直接踩污染。实测：配置 DoH 不可用时，
加兜底前 curl 直接 `Connection was reset`，加之后改用 `223.5.5.5` 拿到正确 IP，正常 204。

## 七、ECH 获取失败导致内核起不来

### 现象

配置里的 DoH 不可用或地址写错（如 `dns.alidns.com/dns-query` 少了 `https://` 前缀）时，
内核日志无限刷「重试...」，端口永不监听，界面只报「内核可能启动失败」。

### 根因

原来的 `prepareECH` 用 `for {}` 无退出条件 —— 只要 DoH 超时（不是秒失败），就永远卡住。
上一轮修成了「重试 10 次 × sleep 2s」，但**单次查询自身要 3-4 秒**，最坏总耗时 ~60 秒，
而 Dart 只等 20 秒。最常见的「超时型坏 DoH」根本走不到降级，内核就被杀了。

### 改法

把「重试次数」换成**墙钟预算**：

```go
const (
    echStartupBudget = 12 * time.Second  // 总耗时 ≤ 12s + 单次查询上限 4s
    echRefreshBudget = 6  * time.Second  // 顺带收紧了重连延迟
    echRetryInterval = 2  * time.Second
)

func prepareECH(budget time.Duration, degradeOnFail bool) error {
    deadline := time.Now().Add(budget)
    for attempt := 1; ; attempt++ {
        // ...查询与解析...
        if time.Until(deadline) <= echRetryInterval { break }
        time.Sleep(echRetryInterval)
    }
    // 降级 / 返回 error
}
```

**预算封顶**：最坏情况（每次吃满 4 秒超时）也在 ~16 秒内完成，Dart 20 秒不再杀它。
正常路径不受影响：真服务器 ECH 第 1 次就成功。

### ★ 降级权只属于启动路径

`prepareECH` 有两个调用点：

| 调用点 | `degradeOnFail` | 失败时 |
|---|---|---|
| 启动（`x-tunnel.go:315`） | `true` | 置位 `echUnavailable` + 返回 `nil` → 内核起得来，改走普通 TLS 1.3 |
| 刷新（`refreshECH`） | `false` | 返回 `error`、**保留原 `echList`**、**不动** `echUnavailable` |

为什么刷新不能降级：刷新由「建连失败」触发，一次瞬时 DoH 抖动（4 秒）就会把整个会话永久降级；
降级后错误里不再含 `"ECH"`，`refreshECH` 再也不会被调用 → **本会话内无法恢复**。

## 八、ECH 预算与 Dart 等待超时错配

### 现象

ECH 降级预算修好了，但 Dart 侧只等 20 秒，TUN 启动还牵涉等通道的 60 秒 —— 时间契约对不上。

### 根因

跨进程/跨语言的时间契约不能只写「我重试几次」，必须写成「我最多占用你多少时间」。
「重试 10 次 × 2s」在单次操作耗时可变时是**假约束**（前面第 7 点）。

### 改法

Dart `_waitPortsReady` 按模式分两种口径：

| 模式 | 等待秒数 | 理由 |
|---|---|---|
| 非 TUN | **25 秒** | ECH 预算 12s + 单次查询上限 4s = 16s，留 9 秒余量 |
| TUN | **90 秒** | ECH 16s + 等通道 60s + TUN 建网卡余量 ≈ 76s < 90s |

两边注释写死了跨层耦合契约：改任一边必须核对另一边。

## 九、启动 / 停止按钮状态不对

### 现象

1. 点「启动代理」后按钮没立刻变灰，还能再点（多点几次会同时启动多个内核进程）；
2. 启动中「停止代理」按钮也不亮，想取消只能干等。

### 根因

`isStarting` 的置位太晚 —— 只在内核进程真正拉起后才置位，而 `start()` 里要 await 端口预检（最多 2 秒），
这个空窗期按钮还是亮的。

### 改法

- `start()` 在**第一个 await 之前就置 `isStarting = true`**，三条失败路径（端口冲突、启动失败、端口未就绪）都清掉它；
- 新增 `isStopping`（`stop()` 开始置位、`finally` 清零），还原系统代理 + 等端口释放要好几秒，期间两个按钮都禁用，防重复停止；
- 按钮逻辑收敛成三个 getter：`canStart` / `canStop` / `isBusy`，配置锁定也统一走 `isBusy`；
- 状态灯和文案补了「停止中…」状态，不再显示旧状态。

用户拍板：**启动中「停止代理」灰显**（`canStop` 不含 `isStarting`），启动状态由左侧黄灯 +「启动中…」表达。

## 十、TUN 模式托盘图标与提权恢复

### 托盘图标不变蓝

TUN 模式下故意不接管系统代理（TUN 优先让位），所以 `proxyReady` 恒为 false →
托盘一直橙，用户以为代理没生效。

改为 `bool get _proxyActive => _app.proxyReady || _app.tunActive;`，
凡「代理是否在生效」的判定都走这个二选一，不能只看系统代理。

### 提权重启后不自动启动

弹框明确承诺「重启后会自动恢复代理并继续启动」，但 `confirmElevation()` 记录的是：

```dart
final wasRunning = isRunning || isStarting; // 此时两个都是 false
```

因为你点「启动代理」时 `start()` 检测到 TUN 未提权就提前 return 了，代理根本还没开始启动，
所以状态全是 false → 写成 `stopped` → 新实例读到 false → 不起。

改为记录**用户意图**而非当时状态：

```dart
final resumeAfterRestart = elevationReason == 'tunStart' || wasRunning;
```

- `tunStart`（点「启动代理」触发）→ **无条件启动**；
- `tunToggle`（拨 TUN 开关）→ 只在「提权前代理正在跑」时才恢复。

## 十一、内核退出前日志丢失

### 现象

排查「TUN 网卡有没有干净卸掉」时，`latest.log` 里缺 `清理完成，退出` 和 `内核已退出`，
但 `kernel.log`（同步写）里完整。缺了这几行就不知道内核到底正常退出了还是崩了。

### 根因

Dart 侧的 `latest.log` 走 `_fileQueue` 异步链写，而 `exit(0)` 会立刻结束进程 ——
队列里还没执行的行整段丢失。

### 改法

在 `close()` 之前加 `flush()`：循环 await 队列直到没有新任务入队（单次 await 不够，
内核 stdout 的最后几个数据块可能晚于 `exitCode` 到达）。最多循环 200 次、每次 5 毫秒，
保证退出前所有日志落盘。

## 十二、版本号三处不同步

### 现象

发版时漏改 `app_version.dart` 的 `defaultValue`，导致自报版本高于 Release 标签，
自动更新**静默失效**——没有任何报错，永远判定「已是最新版本」。

### 改法

- `pubspec.yaml`：`version: 1.1.0+11`
- `lib/services/app_version.dart`：`defaultValue: '1.1.0'`
- `build_local.ps1` / `installer/EchOS.iss` 里的注释示例同步更新

`build_local.ps1` 开头有一致性预检：三者一致 → 通过；
`-Version` 低于 pubspec → 本地测试包警告后继续；其余不一致 → 报错退出。

- 便携版直接替换旧文件；

- 若从 v1.0.9 之前版本升级，分流数据可能过期，应用首次启动会自动检测并提示更新。
