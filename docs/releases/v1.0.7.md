# EchOS-Win v1.0.7

修复两处「用完不清理 / 卸不干净」的遗留问题：自动更新后残留下载的安装包，
以及卸载后残留安装目录。

## 修复一：自动更新后不再残留下载的安装包

**现象**：每次自动更新都会在「下载」文件夹留下一个约 30 MB 的安装包，日积月累。

**原因**：两条更新路径原本都不清理下载包。

- 安装版：`_runSetupSilently` 以 detached 方式启动 Setup.exe 后主进程立即
  `exit(0)`，没人负责删除；而且那一刻 Setup 还在读这个文件，提前删会破坏安装。
- 便携版：就地替换的批处理只 `del "%~f0"`（删它自己），下载的源包原封不动。

**改法**：把删除动作挪到「文件不再被需要」的时刻。

- 安装版：把下载包路径交给更新看门狗，等 Setup 进程退出后再删；句柄尚未释放时
  最多重试 10 次（每次间隔 1 秒），仍失败只记日志，不影响更新结果。
- 便携版：批处理在 `move` 替换成功后删除下载的源包；替换失败则保留，供手动处理。

> 已堆积的历史下载包不会自动消失，本次修复只对之后的更新生效。
> 可在「下载」文件夹里搜索 `EchOS-Win-` 手动清理。

## 修复二：卸载时先关闭 EchOS，避免安装目录残留

**现象**：卸载完成后，`安装目录`（如 `D:\Program Files\EchOS`）仍然留着。

**原因**：卸载时 EchOS 通常还在托盘运行，`echos.exe` 及其依赖的
`flutter_windows.dll`、各插件 DLL 处于占用状态，Inno Setup 删除时报
`code 5 (access denied)`——能删的都删了，被占用的只能留下。此外安装中断遗留的
`is-*.tmp`（Inno 解压临时文件）不在卸载清单里，也会让目录永远非空。

安装侧早有「检测到运行中的应用」页 + `taskkill` 处理，卸载侧原先完全没做。

**改法**（`installer/EchOS.iss`）：

1. **先告知**：卸载向导初始化时若检测到应用在运行，弹确认框说明将自动关闭 EchOS
   并还原系统代理，可以取消（静默卸载不打断）。
2. **优雅退出优先**：写授权标记让应用自己收尾——还原系统代理 → 停止内核进程 →
   退出，最多等 15 秒；超时才 `taskkill` 兜底。
3. **兜底清目录**：`[UninstallDelete]` 删除整个安装目录，清掉 Inno 卸载清单之外的
   残留（如 `is-*.tmp`）。

> 第 2 步的顺序不能反。直接强杀会把系统代理留在「已接管」状态，用户卸载完直接
> 断网——比残留一个目录严重得多。

## 验证

- `flutter analyze`：零问题
- `flutter build windows --release`：编译通过
- Inno Setup 编译：通过（注意 `#13#10` 会被 ISPP 当成预处理指令，已改用 `Chr(13)+Chr(10)`）
- 产物确认：`Remove-Item -LiteralPath`（看门狗删包）与 `del /F /Q`（批处理删包）
  均已进入 `app.so`
- 授权标记退出机制实测有效：写入标记后应用 1 秒内完成还原代理并退出

## 下载哪个

| 文件 | 说明 |
| --- | --- |
| `EchOS-Win-v1.0.7-x64-Setup.exe` | 安装版。写入「应用和功能」，推荐日常使用 |
| `EchOS-Win-v1.0.7-x64-Portable.exe` | 便携版。单文件自解压，免安装，适合 U 盘携带 |

## 升级说明

- 覆盖安装即可，配置存放在 `%APPDATA%\EchOS`，不受影响。
- 自报版本 1.0.6 及以下的客户端均可收到本次更新。
