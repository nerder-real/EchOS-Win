# EchOS-Win v1.0.4

更新时的看门狗改为脚本实现后，补上可观测性；顺带说明一个容易误解的点。

## 改进

- **看门狗增加执行日志**：每次自动更新后，结果会追加到
  `%TEMP%\EchOS_UpdateWatch.log`，形如：

  ```
  2026-09-12 20:18:05 setupPid=12345 alreadyRunning=1 relaunched=0
  ```

  `alreadyRunning=1` 表示安装程序已经把新版拉起来了，看门狗什么都没做
  （这是正常情况）；`relaunched=1` 表示新版没起来、由看门狗补拉。
  有了它就不用再靠猜来判断更新后到底发生了什么。

## 说明：v1.0.3 那次为什么还弹报错窗口

**执行更新的永远是当前正在运行的旧版程序。** 从 v1.0.2 更新到 v1.0.3 时，
跑的是 v1.0.2 的代码，而 v1.0.2 里装的还是那个有问题的批处理看门狗。
修复是 v1.0.3 才带上的，所以从 **v1.0.3 发起的更新**（也就是本次）开始，
不会再有任何命令行窗口弹出。

排查同类问题时，先看安装日志（`%TEMP%\Setup Log *.txt`）里的
`Original Setup EXE:` 是哪一版的包，就能确定责任在谁身上。

另外，安装日志里看不到 `-- Run entry --` 是**正常现象**：
用代码拉起应用不会写这条日志，只有 `[Run]` 段才会写。
要确认新版有没有起来，看 `%APPDATA%\EchOS\logs\latest.log` 的启动横幅最直接。
